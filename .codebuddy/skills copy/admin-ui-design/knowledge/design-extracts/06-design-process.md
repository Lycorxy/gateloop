# 06 — 设计过程

> 来源：frontend-design + redesign-skill + taste-skill §0

## 标准双轮过程

### 第一轮：头脑风暴
生成一个紧凑的设计计划，包含 Token 系统：
1. **色彩**：4-6 个命名 hex 值
2. **字体**：2+ 角色（有特色的标题字体 + 互补的正文字体 + 数据用的工具字体）
3. **布局**：一句话散文描述 + ASCII 线框图
4. **签名元素**：这个页面将被记住的唯一元素

### 第二轮：对照 Brief 审查
审查设计计划，识别并修正任何"模板化默认"。如果某个部分读起来像你为任何类似页面都会生成的东西——修正它，说明你改了什么以及为什么。

### 最终：编代码
严格按修改后的计划编码，每个颜色和字体决策都从计划中派生。

## 重新设计流程（Redesign）

```
扫描(Scan) → 诊断(Diagnose) → 修复(Fix)
```

### Scan
读取代码库。识别框架、样式方案、当前设计模式。

### Diagnose
跑完整设计审计（见 `07-anti-patterns.md`）。列出所有发现的通用模式、弱点、缺失状态。

### Fix
在现有技术栈上针对性升级。不从头重写。改进现有代码。

## 设计写前自检

- [ ] 已输出一行 "设计读"
- [ ] 已设置三旋钮值
- [ ] 已选定设计系统/审美方向
- [ ] 色彩：1个主色，Token系统完整
- [ ] 字体：有特色的标题 + 互补的正文
- [ ] 布局：Hero 内容 ≤ 4个文本元素
- [ ] 状态：Loading/Empty/Error 全覆盖
- [ ] 没有 AI 默认反模式

## 设计后发货检查

- [ ] 所有颜色来自 CSS Variable
- [ ] 所有间距来自 Space Token
- [ ] 组件尺寸符合规范
- [ ] 四模式主题兼容（Light/Dark）
- [ ] 无硬编码色值残留
- [ ] 导航桌面端单行
- [ ] Hero 在首屏内
- [ ] 每页 eyebrow 数 ≤ sectionCount/3
- [ ] CTA 文字桌面端单行
- [ ] 同一意图 CTA 不重复
