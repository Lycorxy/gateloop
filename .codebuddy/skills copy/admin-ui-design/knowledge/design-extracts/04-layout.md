# 04 — 布局原则

> 来源：taste-skill §4.3-4.7 + redesign-skill + frontend-design

## Hero 区域硬规则

### 必须适配首屏
- 头条：桌面端最多 2 行
- 副文：最多 **20 词**，最多 3-4 行
- CTA 必须无需滚动可见
- Hero 顶部 padding 上限 `pt-24`（≈6rem）

### Hero 内容堆叠纪律（最多 4 个文本元素）
1. Eyebrow（可选，0 或 1 个）
2. 头条（最多 2 行）
3. 副文（最多 20 词，4 行）
4. CTA（1 主 + 最多 1 次）

**Hero 内禁止**：小标签、trust徽标条、价格预告、特性列表、社交头像行

### 导航
- 桌面端必须单行，上限 80px
- 如果放不下 → 缩短标签、删除次要项、或折叠
- 默认高度：64-72px

## 布局多样性规则

### 反居中偏见
`DESIGN_VARIANCE > 4` 时禁止居中 Hero。强制使用：
- 分屏（50/50）
- 左对齐内容 + 右对齐资产
- 非对称留白
- 滚动固定结构

### Bento 网格
- 必须有多样的视觉变化（图片/渐变/色彩背景），不能全是白底文字卡片
- 单元格数量 = 内容数量，不留空白格
- 2-3 个单元格必须用真实视觉资产（非纯文字）
- 每页的 Bento 网格最多出现一次

### 布局重复禁令
- 同一个布局族（3列图片卡片、全宽引用、图文分屏）每页最多出现 **1 次**
- Alternating zigzag（左图右文→左文右图交替）最多连续 2 个 section
- 8 个 section 的页面至少使用 4 个不同布局族

### Eyebrow 克制
- 最多每 **3 个 section** 用 1 个 eyebrow
- 机械检查：统计全页 `uppercase tracking` 标签数，超过 `ceil(sectionCount/3)` 则失败
- 替代方案：直接去掉。标题本身就够了

### "左大标题 + 右小段落"分头模式 → 禁止
Section 标题应该有一个焦点信息。如果需要标题+解释段落，垂直堆叠（标题在上，正文在下，max-width 65ch）。

## 卡片与阴影

- Card 只在 elevation 传达真实层级时才使用
- 否则用 `border-t`、`divide-y`、或留白分组
- 阴影必须染上背景色相，禁止纯黑 drop-shadow
- `VISUAL_DENSITY > 7` 时禁止卡片容器

## 响应式

- 断点：`sm 640`、`md 768`、`lg 1024`、`xl 1280`、`2xl 1536`
- 用 `min-h-[100dvh]` 替代 `h-screen`
- 用 CSS Grid 替代 flexbox 百分比数学
- 每个多列布局必须在组件内声明 `< 768px` 回退方案

## 管理系统布局

- 页面→内容区：padding 20px
- 卡片→内部：padding 24px
- 卡片→卡片：gap 16-20px
- 表单项间距：margin-bottom 20px
- 按钮组间距：gap 8px
