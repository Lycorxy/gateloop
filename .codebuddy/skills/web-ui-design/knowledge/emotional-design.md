# 情感化设计与交互质感（Emotional Design & Interaction Craft）

> 决定用户"喜不喜欢"一个工具的，不是颜色和图标，而是**交互的质感**和**信息组织的节奏**。
> 参考：Linear 的"精确感"、Things 3 的"愉悦感"、Raycast 的"响应感"、Arc 的"流畅感"

---

## 一、信息节奏（Information Rhythm）

### 核心原则：张弛有度，不要全程等密度

一个让人喜欢的界面，信息密度是**有节奏变化**的——不是从头到尾一样密，也不是全程稀疏。

```
❌ 不好：全程等密度，像 Excel 表格
┌────────────────────────────────┐
│ 密 密 密 密 密 密 密 密 密 密  │
│ 密 密 密 密 密 密 密 密 密 密  │
│ 密 密 密 密 密 密 密 密 密 密  │
└────────────────────────────────┘

✅ 好：有疏有密，像呼吸
┌────────────────────────────────┐
│ 疏 — 标题区，留白多，建立预期   │
├────────────────────────────────┤
│ 密 密 密 — 列表区，信息密集     │
│ 密 密 密                       │
├────────────────────────────────┤
│ 疏 — 操作区，留白，降低压力     │
└────────────────────────────────┘
```

### 密度策略表

| 区域 | 密度 | 间距 | 字号 | 原因 |
|------|------|------|------|------|
| **标题/Header** | 疏 | 16-24px | 13-14px/700 | 建立层级，给视觉喘息 |
| **工具栏** | 中 | 8px | 11px | 紧凑但不挤，操作就绪 |
| **列表/数据** | 密 | 4-6px | 11px | 信息密度优先 |
| **详情区** | 中 | 8-12px | 11-12px | 可读性优先 |
| **操作区** | 疏 | 12-16px | 11px | 降低误触压力 |
| **空状态** | 极疏 | 32px+ | 12px | 消除焦虑感 |

### 节奏的 3 个黄金法则

1. **首屏最后一个元素和底部之间留 1 个 `--space-4`(16px) 的呼吸** — 不要让内容贴底
2. **不同功能区之间用 1px 分割线 + 8px 间距分隔** — 而非用大间距硬隔
3. **列表项内部间距 < 列表项之间间距** — 形成天然的分组感

## 二、视觉动线引导（Visual Flow）

### 用户眼睛怎么扫描界面

```
F 型扫描（列表/表格场景）
┌──────────────────────────────┐
│ ████████████████████ ← 先横扫标题 │
│ ████ ← 再竖扫左侧关键词        │
│      ████                    │
│      ████ ← 发现感兴趣的后横扫  │
│           ████               │
└──────────────────────────────┘

Z 型扫描（工具栏 + 内容场景）
┌──────────────────────────────┐
│ ①──────────────→ ②           │
│                    ↓         │
│                    ↓         │
│ ③ ←────────────── ④          │
└──────────────────────────────┘
```

### 引导眼睛的 5 个手法

| 手法 | 实现 | 效果 |
|------|------|------|
| **大小对比** | 标题 14px / 正文 12px / 元数据 11px | 眼睛自动从大到小 |
| **颜色权重** | 主操作用主色，次要操作用中性色 | 眼睛先看到彩色 |
| **留白指向** | 关键元素周围留更多白 | 留白 = 视觉聚光灯 |
| **对齐线** | 左对齐的标签形成竖向引导线 | 眼睛沿线移动 |
| **编号/序号** | 有序步骤加数字圆圈 | 明确的阅读顺序 |

### 反模式：视觉竞争

```
❌ 多个元素同时争夺注意力
┌──────────────────────────────┐
│  [红色按钮] [蓝色按钮] [绿色按钮] │  ← 三个等权彩色按钮
│  ★ 重要     ★ 重要    ★ 重要   │  ← 三个星标
└──────────────────────────────┘

✅ 一个焦点，其余退后
┌──────────────────────────────┐
│  [主操作]   次操作   次操作     │  ← 一个主色，两个中性
└──────────────────────────────┘
```

## 三、微交互质感（Micro-interaction Craft）

### 什么是"质感"

质感 = 每个交互都给出**恰到好处**的反馈。不是反馈越多越好，而是反馈的**时机、强度、时长**都精确。

### 质感评分表

| 等级 | 描述 | 例子 |
|------|------|------|
| 🚫 粗糙 | 无反馈或反馈缺失 | 点击按钮无视觉变化 |
| ⚠️ 及格 | 有基本反馈但不够精致 | hover 只变色，无过渡 |
| ✅ 良好 | 有过渡，时机正确 | hover 150ms 颜色过渡 |
| ⭐ 精致 | 过渡 + 微妙变形 + 状态完整 | hover 变色 + 微缩放 + active 按下 |

### 按钮的 6 种状态完整规范

```css
/* Default — 待命态 */
.btn {
  background: var(--neutral-01);
  border: 1px solid var(--neutral-03);
  color: var(--neutral-07);
  transition: all 150ms var(--ease-standard);
}

/* Hover — 邀请操作（颜色变深，有过渡） */
.btn:hover {
  background: var(--neutral-02);
  border-color: var(--neutral-04);
  color: var(--neutral-08);
}

/* Active — 确认按下（微缩放，即时响应） */
.btn:active {
  transform: scale(0.98);        /* 关键：0ms，瞬时响应 */
  background: var(--neutral-03);
}

/* Focus — 键盘可达（focus ring） */
.btn:focus-visible {
  outline: none;
  box-shadow: 0 0 0 2px var(--primary-bg), 0 0 0 3px var(--primary);
}

/* Disabled — 不可操作（降低存在感） */
.btn:disabled {
  opacity: 0.35;
  cursor: not-allowed;
}

/* Loading — 操作进行中（保持按钮尺寸不变） */
.btn.loading {
  color: transparent;             /* 文字隐藏 */
  pointer-events: none;
}
.btn.loading::after {
  content: '';
  position: absolute;
  width: 14px; height: 14px;
  border: 2px solid var(--neutral-04);
  border-top-color: var(--primary);
  border-radius: 50%;
  animation: spin 0.6s linear infinite;
}
```

### 质感的关键：响应速度

| 操作类型 | 可接受延迟 | 超过则 |
|---------|-----------|--------|
| Hover/Focus | 0ms（CSS transition） | 感觉迟钝 |
| Click 反馈 | < 100ms | 感觉卡顿 |
| 数据加载 | < 200ms 直接显示 | 显示 skeleton |
| 数据加载 | 200-1000ms | 显示 skeleton |
| 数据加载 | > 1000ms | 显示 loading + 预估时间 |
| 操作完成反馈 | 即时（Toast 200ms 出现） | 用户重复点击 |

### "Snappy"（响应灵敏）的 3 个秘诀

1. **`transform` 和 `opacity` 做动画** — 不触发布局重排，GPU 加速
2. **`will-change: transform`** — 提前告知浏览器优化
3. **`contain: layout`** — 隔离重绘范围

```css
/* ✅ 用 transform/opacity，GPU 加速 */
.item { transition: transform 150ms, opacity 150ms; }
.item:hover { transform: translateY(-1px); }

/* ❌ 用 top/left/width，触发重排 */
.item { transition: top 150ms, width 150ms; }
```

## 四、认知负荷管理（Cognitive Load）

### Miller 法则：人脑同时处理 7±2 个信息块

| 场景 | 同时展示 | 策略 |
|------|---------|------|
| 导航菜单 | ≤ 7 项 | 直接展示 |
| 表单字段 | ≤ 5 个 | 单组展示 |
| 表单字段 | 6-15 个 | 分组（2-3 组） |
| 表单字段 | > 15 个 | 步骤向导 |
| 列表项 | 不限 | 但每行信息 ≤ 5 个 |
| 过滤条件 | ≤ 4 个 | 全部可见 |
| 过滤条件 | 5-8 个 | 常用可见 + 高级折叠 |

### 信息分组的 3 个原则

1. **亲密性原则** — 相关的信息物理距离近
```
✅ 好：标签和输入框紧贴
Label
[input    ]    ← 间距 2px

❌ 坏：标签和输入框分离
Label

[input    ]    ← 间距 16px，视觉脱节
```

2. **相似性原则** — 同类操作样式一致
```
✅ 所有"删除"按钮都是红色 ghost
✅ 所有"导出"按钮都有下载图标
✅ 所有"主操作"都是 primary 样式
```

3. **连续性原则** — 操作流程有视觉引导
```
开始录制 → [停止] → [导出]
   ↑ 蓝色    ↑ 变灰   ↑ 蓝色（引导下一步）
```

### 降低认知负荷的 5 个手法

| 手法 | 实现 | 效果 |
|------|------|------|
| **默认值** | 给常用操作设默认选中 | 减少决策 |
| **渐进披露** | 高级选项折叠 | 首屏不吓人 |
| **视觉分组** | 用卡片/分割线/间距分组 | 信息有结构 |
| **状态提示** | 录制中显示计数 | 用户知道进度 |
| **操作引导** | 按钮文案说明结果而非动作 | "导出 JSON" > "导出" |

## 五、开发者工具的键盘优先设计

### 为什么键盘重要

开发者是**高频键盘用户**，一个不支持的快捷键的工具会让人烦躁。

### 必备快捷键

| 快捷键 | 功能 | 场景 |
|--------|------|------|
| `Cmd/Ctrl + K` | 命令面板 / 全局搜索 | 快速跳转 |
| `Cmd/Ctrl + F` | 聚焦过滤框 | 列表过滤 |
| `↑` `↓` | 列表项导航 | 不需要鼠标 |
| `Enter` | 选中/展开 | 确认操作 |
| `Esc` | 关闭/取消 | 通用退出 |
| `Cmd/Ctrl + C` | 复制选中项 | 快速复制 |
| `Cmd/Ctrl + E` | 导出当前 | 快速导出 |
| `Space` | 切换开关 | 启用/禁用 |

### 焦点管理

```tsx
// 1. 打开面板自动聚焦搜索框
useEffect(() => {
  searchInputRef.current?.focus();
}, []);

// 2. 列表支持方向键导航
const handleKeyDown = (e) => {
  if (e.key === 'ArrowDown') setSelectedIndex(i => Math.min(i + 1, max));
  if (e.key === 'ArrowUp') setSelectedIndex(i => Math.max(i - 1, 0));
  if (e.key === 'Enter') onSelect(items[selectedIndex]);
};

// 3. Esc 关闭弹窗
useEffect(() => {
  const onKey = (e) => { if (e.key === 'Escape') onClose(); };
  window.addEventListener('keydown', onKey);
  return () => window.removeEventListener('keydown', onKey);
}, []);
```

### Focus Ring 规范

```css
/* 只在键盘导航时显示 focus ring，鼠标点击不显示 */
*:focus { outline: none; }
*:focus-visible {
  outline: 2px solid var(--primary);
  outline-offset: 2px;
}
```

## 六、交互反馈的层次

### 三层反馈体系

```
Level 1: 即时反馈（0-100ms）
  └─ 视觉变化：颜色/缩放/边框
  └─ 用户感知："我点到了"

Level 2: 过程反馈（100ms-2s）
  └─ Loading 态：spinner/skeleton/进度
  └─ 用户感知："正在处理"

Level 3: 结果反馈（操作完成后）
  └─ Toast/状态变化/数据刷新
  └─ 用户感知："完成了"
```

### 每种操作的反馈组合

| 操作 | L1 即时 | L2 过程 | L3 结果 |
|------|---------|---------|---------|
| 点击按钮 | 按下缩放 | — | Toast 成功 |
| 提交表单 | 按钮变 loading | spinner | Toast + 跳转 |
| 复制内容 | 按钮变色 | — | "已复制" tooltip |
| 删除项目 | 行变红 | — | 行消失动画 + Toast |
| 导出文件 | 按钮变 loading | 进度 | 浏览器下载 + Toast |

### 复制操作的精致反馈

```tsx
// ❌ 不好：复制后无反馈，用户不确定是否成功
onClick={() => navigator.clipboard.writeText(url)}

// ✅ 好：复制后按钮短暂变成"已复制"
const [copied, setCopied] = useState(false);
const handleCopy = () => {
  navigator.clipboard.writeText(url);
  setCopied(true);
  setTimeout(() => setCopied(false), 1500);
};

// 渲染
<button onClick={handleCopy}>
  {copied ? <Check size={14} /> : <Copy size={14} />}
  {copied ? 'Copied' : 'Copy'}
</button>
```

## 七、让工具"有温度"的 5 个细节

### 1. 智能默认值

```
❌ 打开 Mock 编辑器，所有字段空白，用户不知道填什么
✅ 打开 Mock 编辑器，URL 已预填当前接口，方法已预选
```

### 2. 操作可撤销而非确认

```
❌ 删除规则前弹 Modal："确定删除？"
✅ 删除后底部 Toast："已删除，[撤销]"（5s 内可撤销）
```

**原则**：宁可让用户撤销，也不要用 Modal 打断流程。

### 3. 状态持久化

```
❌ 关闭面板再打开，过滤条件清空了
✅ 过滤条件、选中项、Tab 状态持久化到 localStorage
```

### 4. 数据变化的感知

```
❌ 新接口请求进来，列表无任何变化提示
✅ 新请求以 stagger 动画入场，或顶部短暂显示"3 new"
```

### 5. 空状态有出路

```
❌ "暂无数据"
✅ "暂无数据 — 尝试清除过滤条件" + [清除] 按钮
```

## 八、布局的呼吸感（Breathing Room）

### 间距不是越大越好，也不是越小越好

```
❌ 太挤（4px 全局）— 信息密集但焦虑
┌──────────────┐
│A B C D E F G H│
│I J K L M N O P│
└──────────────┘

❌ 太松（24px 全局）— 浪费空间且不聚焦
┌──────────────┐
│              │
│   A          │
│              │
│   B          │
│              │
└──────────────┘

✅ 有节奏（4-8-12-16 交替）
┌──────────────┐
│              16px
│   标题区     │
│              12px
│  ┌────────┐ 8px
│  │ item 1 │
│  ├────────┤ 4px
│  │ item 2 │
│  └────────┘ 12px
│   操作区     │
│              16px
└──────────────┘
```

### 黄金间距比例

| 关系 | 间距 | Token |
|------|------|-------|
| 标签 → 输入框 | 4px | `--space-1` |
| 输入框内文字 → 边框 | 8px | `--space-2` |
| 同组元素之间 | 8px | `--space-2` |
| 不同组之间 | 12px | `--space-3` |
| 不同区域之间 | 16px | `--space-4` |
| 区块底部留白 | 16px | `--space-4` |

### 边距 vs 间距的区别

```
卡片内边距（padding）= 12px     ← 内容与卡片边的距离
卡片之间间距（gap）= 8px        ← 卡片与卡片的距离

原则：padding > gap（内容比结构更需要呼吸）
```

## 九、"好设计"检查清单

设计完成后逐条检查：

### 信息组织
- [ ] 首屏 P0 信息无需操作即可见
- [ ] 信息有清晰的分组（亲密性原则）
- [ ] 同屏焦点 ≤ 2 个（主焦点 + 次焦点）
- [ ] 视觉动线从左上到右下自然流动

### 交互质感
- [ ] 每个按钮有 6 种状态（default/hover/active/focus/disabled/loading）
- [ ] 点击反馈 < 100ms
- [ ] hover 过渡 120-150ms
- [ ] 操作完成有 Toast 或状态变化反馈
- [ ] 破坏性操作可撤销（而非弹 Modal 确认）

### 布局节奏
- [ ] 不同区域密度有变化（非全程等密度）
- [ ] 内容底部有 16px 呼吸空间
- [ ] 同组间距 < 跨组间距
- [ ] 卡片 padding > 卡片 gap

### 认知负荷
- [ ] 每行信息 ≤ 5 个元素
- [ ] 过滤条件 ≤ 4 个全部可见
- [ ] 高级选项折叠（渐进披露）
- [ ] 按钮文案说明结果（"导出 JSON" > "导出"）

### 可达性
- [ ] 支持键盘导航（Tab/Enter/Esc/方向键）
- [ ] focus-visible 有 focus ring
- [ ] 打开面板自动聚焦搜索框
- [ ] Esc 关闭弹窗

### 情感化
- [ ] 空状态有引导操作（不只说"暂无数据"）
- [ ] 复制操作有"已复制"反馈
- [ ] 新数据入场有 stagger 动画
- [ ] 状态持久化（关闭再打开恢复上次状态）
