# 前后端联调（Go 后端 + 前端）v3.1

## 🛑 入口守卫

```
本 Skill 加载后必须按 Step 0→1→...→5 顺序执行全部步骤。
每步播报完成消息，未播报 = 未执行 = 违规。
禁止跳步，禁止改视图/逻辑层代码。
```

**核心定位：不是"替换接口"，而是"在数据层做精准外科手术，让视图和逻辑层完全无感"。**

> 🧠 **设计哲学**：像一个经验丰富的前端架构师那样逐步推理——先划清边界确认安全，
> 再按接口逐个迁移，每一步都有约束检查，绝不让改动蔓延到不该碰的地方。

核心策略：**只在数据层加一个 transform 函数**，视图和逻辑层不动。

核心目标排序：**数据正确 > 最小改动 > 增量验证 > 零蔓延**

---

## 何时使用 / 何时不使用

**应该触发：**

- "前后端联调"、"接口对接"、"mock替换"、"API对接"
- 项目中存在 mock 数据需要切换到真实后端
- 后端接口已就绪，需要前端接入

**不应触发：**

- 纯后端开发 / 纯前端 UI 开发
- 数据库设计 / NoSQL 设计
- 纯 mock 数据编写（无后端对接需求）

└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐

## Step 1 — 划定边界 [低自由度 · 强制]

> **开始前只读操作，不动代码。** 像外科医生术前标记切口位置。

### 1.1 扫描清单（逐条执行）

```typescript
// 并行扫描，获取全局视图
search_content('mock', { glob: '*.{ts,tsx,js}' }) // 找到所有 mock 引用
search_content('@/mock/', { glob: '*.{ts,tsx}' }) // mock 导入路径
read_file('{go_backend_handler_or_proto}') // 后端接口定义
list_dir('src/api/') // 已有 API 层结构
```

### 1.2 边界判定（强制检查）

```
□ 列出所有涉及的 mock 文件和调用位置
□ 读 Go 后端接口定义，对比字段差异
□ 数改动的文件和模块数量
```

**边界约束（铁律 4）**：

```
涉及 > 3 个模块  →  ⛔ 暂停，方向可能不对
涉及 > 5 个文件  →  ⛔ 暂停，考虑分批
需要改组件内部   →  ⛔ 重新设计，组件不该动
字段差异 > 10 个 →  ⛔ 暂停，确认接口文档
```

> 完成播报：`"✅ Step 1 边界划定完成：{N}个接口 / {N}个文件 / {N}个模块"` — 超出边界必须暂停。
>
> **验证检查点：**
> ```
> □ mock 文件和调用位置已列出
> □ Go 后端接口已读取，字段差异已对比
> □ 改动文件 ≤ 5 个，模块 ≤ 3 个
> □ 无需修改组件内部逻辑
> ```
>
> 🔒 **强制约束**：此步骤不可跳过。不划定边界就动代码 = 违规。

## Step 2 — 写 transform 函数 [低自由度 · 强制]

> **核心一步**：不管有没有 mock，始终保持：后端响应 → transform → 组件 props。
> 这是联调的"外科手术刀"——只切数据层，不动其他。

### 2.1 规范（铁律 2）

```
输入类型  = 后端响应类型（ApiResponse / proto 生成类型）
输出类型  = 组件 props 类型（前端自定义类型）
函数职责  = 仅做字段映射，不做业务逻辑
函数行数  ≤ 50 行
```

### 2.2 模板

```typescript
// src/api/transform.ts — 唯一需要新增/修改的文件

import type { ApiResponse } from './types' // 后端响应的类型
import type { Task } from '@/types' // 组件需要的类型

export function transformTaskList(res: ApiResponse): Task[] {
    return res.data.list.map((item) => ({
        id: item.id,
        name: item.task_name, // 字段映射：下划线 → 驼峰
        status: STATUS_MAP[item.status] // 值映射：数字 → 字符串
    }))
}

const STATUS_MAP: Record<number, string> = {
    1: '待处理',
    2: '进行中',
    3: '已完成'
}
```

### 2.3 反模式检查

```
✗ transform 中有 .filter()  → 业务逻辑，不属于 transform
✗ transform 中有 if/else    → 业务判断，不属于 transform
✗ transform 输出含后端原始字段名 → 应映射为前端类型
✓ transform 纯字段映射 + 值转换
```

> 完成播报：`"✅ Step 2 transform 完成：{函数名} ({N}个字段映射)"` — 未播报不得进入 Step 3。
>
> **验证检查点：**
> ```
> □ 输入类型 = 后端响应类型
> □ 输出类型 = 组件 props 类型
> □ 函数 ≤ 50 行，仅字段映射
> □ 无业务逻辑（.filter / if/else）
> ```
>
> 🔒 **强制约束**：此步骤不可跳过。每个接口必须有 transform 函数。

## Step 3 — 替换 mock 调用 [低自由度 · 强制]

### 3.1 有 mock 场景

```typescript
// 替换前
const [tasks] = useState(mockTasks)

// 替换后
useEffect(() => {
    fetchTaskList().then((res) => setTasks(transformTaskList(res)))
}, [])
```

### 3.2 无 mock 场景

直接走 Step 2（定义类型 → 写 API 函数 → 写 transform → 组件调用），不需要替换操作。

### 3.3 成对约束

```
✗ 只删了 mock 但没加 transform  → 违规
✗ 只加了 transform 但没删 mock  → 违规
✓ 删除 mock + 添加 transform 成对出现
```

> 完成播报：`"✅ Step 3 mock 替换完成：{接口名}"` — 未播报不得进入 Step 4。
>
> **验证检查点：**
> ```
> □ mock 数据已删除（或声明为新建接口无 mock）
> □ transform 函数已添加（成对出现）
> □ 数据获取方式已更新（fetch + transform）
> ```
>
> 🔒 **强制约束**：此步骤不可跳过。若接口无 mock（新建接口），声明跳过：
> `⏭️ [跳过] Step 3 mock替换 | 理由：{接口名}无mock数据，为新建接口 | 风险：无`

## Step 4 — 逐接口验证 [低自由度 · 强制]

> **铁律 3：增量验证**。一次只做一个接口，做完验证再继续下一个。

### 4.1 验证流程

```
接口 A：transform → 替换调用 → 验证 → 提交
接口 B：transform → 替换调用 → 验证 → 提交
接口 C：...
```

**禁止**：一次改完所有接口，最后一起验证。

### 4.2 每个接口验证清单

```
□ API 返回正常，transform 字段映射正确
□ 页面表现与之前 mock 版本一致
□ npm run build 通过
□ go build ./... 通过（如有 Go 后端改动）
```

> 完成播报：`"✅ Step 4 接口验证通过：{接口名}"` — 有错误必须修复后再继续。
>
> 🔒 **强制约束**：此步骤不可跳过。跳过验证 = 违规。

---

## Step 5 — 清理与全量验证 [低自由度 · 强制]

### 5.1 清理清单

```
□ 删除所有 mock 文件和 @/mock/ 引用
□ 移除 USE_MOCK / MOCK_ENABLED 等环境切换代码
□ 确认没有残留的 mock import
□ 确认没有未使用的 transform 函数
```

### 5.2 全量验证清单（铁律 5 + 反模式）

```
□ 所有 mock 文件和 import 已删除
□ 清理了 USE_MOCK / MOCK_ENABLED 等环境切换代码
□ 每个接口有对应的 transform 函数
□ transform 输入类型 = 后端类型，输出类型 = 组件类型
□ 组件代码未被修改（或仅修改了数据获取方式）
□ 未改动无关模块
□ npm run build 通过
□ go build ./... 通过
```

> 完成播报：`"✅ Step 5 清理与验证完成：{N}个接口联调完毕"` — 未通过编译验证不得交付。
>
> 🔒 **强制约束**：此步骤不可跳过。未清理 mock 残留 = 违规。

## 错误处理

| 场景               | 处理方式                            |
| ------------------ | ----------------------------------- |
| 后端接口未就绪     | 不要提前对接，等接口可用            |
| 字段不稳定         | transform 中加默认值兜底，记录 TODO |
| 组件缺字段         | 补充 transform 输出，不改组件       |
| 后端多余字段       | 不放 transform 输出                 |
| 字段差异 > 10 个   | ⛔ 暂停，确认接口文档               |
| 改动蔓延 > 3 模块  | ⛔ 立即暂停，重新审视方向           |
| 需要改组件内部逻辑 | ⛔ 重新设计，组件不该动 → 先 Ask    |
