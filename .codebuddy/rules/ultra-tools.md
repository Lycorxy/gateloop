## 3. 调用规范

### 3.1 工具调用优先级（强制）

当用户请求某个功能时，必须按以下优先级查找并调用工具：

```
┌─────────────────────────────────────────────────────────┐
│  用户请求（如：读取 Figma 链接、执行命令等）            │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│  1️⃣ 用户插件 (nut_<plugin>)                             │
│     检查是否有用户定义的插件能处理此请求                │
│     ✅ 有 → 调用用户插件                                │
│     ❌ 无 → 继续下一级                                  │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│  2️⃣ 内置工具 (nut_exec, nut_npm_run, nut_git 等)        │
│     检查是否有 node-ultra 内置工具能处理此请求          │
│     ✅ 有 → 调用内置工具                                │
│     ❌ 无 → 继续下一级                                  │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│  3️⃣ 模型内置工具 (read_file, search_content 等)        │
│     使用模型/IDE 提供的内置工具                         │
│     ✅ 有 → 调用模型工具                                │
│     ❌ 无 → 不执行                                      │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│  4️⃣ 不执行                                              │
│     告知用户当前没有可用工具处理此请求                  │
└─────────────────────────────────────────────────────────┘
```

### 3.2 终端命令执行优先级

执行终端命令时，必须遵循以下优先级：

| 优先级 | 工具 | 说明 | 何时使用 |
|--------|------|------|----------|
| 1️⃣ **首选** | `nut_exec` | 跨端命令执行 | 默认使用 |
| 1️⃣ **首选** | `nut_npm_run` | npm 脚本执行 | 执行 npm scripts |
| 1️⃣ **首选** | `nut_exec_shell` | Shell 命令 | 需要管道/重定向 |

## 4. 交互规范（强制）

### 4.1 单个命令格式

每次执行 MCP 工具或终端命令，必须包含**开始**和**结束**两部分：

```
🔄 [开始] 读取 package.json 文件的 scripts 部分

[执行 mcp_call_tool / read_file / nut_exec 等]

✅ [完成] package.json 读取成功，包含 5 个 scripts
```

### 4.2 多个命令格式

连续执行多个命令时，必须**标注序号**，每个命令都要有开始和结束：

```
🔄 [1/3] 开始读取 src/index.ts 文件

[执行 read_file]

✅ [1/3] src/index.ts 读取成功（共 150 行）

---

🔄 [2/3] 开始执行构建命令

[执行 nut_npm_run script="build"]

✅ [2/3] 构建成功，生成 dist 目录

---

🔄 [3/3] 开始检查 Git 状态

[执行 nut_git args=["status"]]

✅ [3/3] Git 状态：2 个文件已修改
```

### 4.3 状态标识

| 标识 | 含义 | 使用场景 |
|------|------|----------|
| 🔄 [开始] | 即将执行 | 命令执行前 |
| 🔄 [N/M] | 第 N 个命令（共 M 个） | 多命令时 |
| ✅ [完成] | 执行成功 | 命令执行后 |
| ❌ [失败] | 执行失败 | 出错时 |

## 5. 使用说明

### 5.1 优先级决策流程

1. **收到用户请求** → 分析需要什么功能
2. **查找用户插件** → 检查是否有匹配的 `nut_<plugin>` 插件
3. **查找内置工具** → 检查是否有匹配的 `nut_exec`/`nut_npm_run` 等
4. **查找模型工具** → 使用 IDE 内置的 `read_file`/`search_content` 等
5. **兜底处理** → 终端命令可用 `execute_command`，其他告知用户无可用工具
