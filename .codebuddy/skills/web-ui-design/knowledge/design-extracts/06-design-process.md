# 06 — 设计过程（强制流程）

---

## 一、标准设计流程

```
Phase 0: 设计读 → 明确场景/用户/约束
     ↓
Phase 1: 信息架构 → 分级/分组/排优先级
     ↓
Phase 2: 方案设计 → 至少 2 方案 + 评分对比
     ↓
Phase 3: 交互论证 → 每个节点说理由
     ↓
Phase 4: 视觉规范 → Token/间距/颜色/层级
     ↓
Phase 5: 6 项检测 → 全 PASS 才产出
     ↓
Phase 6: 代码实现 → 按规范编码
     ↓
Phase 7: 代码审计 → 间距/颜色/交互/布局/体验
```

---

## 二、每个 Phase 的输出物

### Phase 0 输出

```markdown
设计读："读此为 [页面类型]，面向 [用户]，核心诉求 [动词+名词]，约束 [空间/场景]。"
三旋钮：DENSITY=[?] INTERACTION=[?] REFINEMENT=[?]
```

### Phase 1 输出

```markdown
## 信息架构

### P0 (核心，必须首屏可见)
- [...]
- [...]

### P1 (重要，1 步可达)
- [...]

### P2 (次要，2 步可达)
- [...]

### P3 (可选，可隐藏)
- [...]

### 高频操作
1. [...]
2. [...]
3. [...]
```

### Phase 2 输出

```markdown
## 方案对比

### 方案 A: [名称]
[ASCII 线框图]
信息策略：[...]
交互路径：[...]

### 方案 B: [名称]
[ASCII 线框图]
信息策略：[...]
交互路径：[...]

### 评分矩阵
| 维度（权重） | 方案 A | 方案 B |
|...|...|...|

### 决策
选 [X]，因为 [...]
```

### Phase 3 输出

```markdown
## 交互设计

### [交互点 1]
- 可选方案：[...]
- 选择：[...]
- 理由：[...]

### [交互点 2]
- 可选方案：[...]
- 选择：[...]
- 理由：[...]
```

### Phase 4 输出

```markdown
## 视觉规范
- 主色：[hex] — 用途：[...]
- 中性色：[体系]
- 间距：页面 padding [?]px，组件间 [?]px，组件内 [?]px
- 字号层级：H1 [?]px / H2 [?]px / Body [?]px / Caption [?]px
- 签名元素：[这个设计的记忆点是什么]
```

### Phase 5 输出

```markdown
## 设计检测报告

### ✅ 布局合理性 [PASS/FAIL]
- [x] 首屏信息完整度
- [x] 信息层级清晰度
- ...

### ✅ 交互合理性 [PASS/FAIL]
- [x] 高频操作触达
- ...

### ✅ 间距系统 [PASS/FAIL]
- [x] Token 使用
- ...

### ✅ 视觉质量 [PASS/FAIL]
- ...

### ✅ 用户体验 [PASS/FAIL]
- ...

### ✅ 现代感 [PASS/FAIL]
- ...
```

---

## 三、检测不通过的处理

```
如果任何一项检测 FAIL：
1. 标注具体哪个检查项不通过
2. 分析原因
3. 提出修正方案
4. 重新输出修正后的设计
5. 再次检测直到全部 PASS

不允许带着 FAIL 产出最终代码。
```

---

## 四、设计后审计（Code Audit）

代码产出后，强制执行以下自审：

```markdown
## 代码审计清单

### 间距审计
提取所有 margin/padding/gap 值：
- [ ] 全部为 4 的倍数
- [ ] 无 magic number (如 7px, 13px, 15px)
- [ ] 层级关系正确（内 < 间 < 组 < 区）

### 颜色审计
提取所有颜色值：
- [ ] 无硬编码 hex/rgb
- [ ] 全部来自 CSS Variable / Token
- [ ] 主色使用 ≤ 5% 面积

### 一致性审计
- [ ] 同类按钮尺寸一致
- [ ] 同级组件圆角一致
- [ ] 同级文字大小一致
- [ ] 对齐基线 ≤ 3 种

### 状态审计
- [ ] 空态处理
- [ ] 加载态（Skeleton）
- [ ] 错误态
- [ ] Hover/Active/Focus
- [ ] Disabled

### 体验审计
- [ ] P0 信息首屏可见
- [ ] 核心操作 ≤ 3 步
- [ ] 可点击有 cursor:pointer
- [ ] Focus 可见
```

## 五、简化流程（小改动适用）

对于小型改动（修改样式/微调布局），可简化为：

```
1. 快速设计读（1 句话）
2. 直接方案（无需对比，但说明为什么这样做）
3. 间距+颜色快速自检
4. 产出代码
```

满足条件：
- 改动范围 ≤ 1 个组件
- 不涉及布局重构
- 不涉及新增交互模式

## 六、"为什么这样做"检查

在产出任何设计代码前，对每个关键决策回答：

```
Q: 为什么用这个布局？
A: 因为 [...]

Q: 为什么用这个交互方式？
A: 因为 [...]

Q: 为什么用这个间距？
A: 因为 [...]（必须引用 Token 名）

Q: 为什么用这个颜色？
A: 因为 [...]（必须说明语义）

Q: 这个设计的记忆点是什么？
A: [...]

如果任何一个问题回答不了 → 设计不够好，需要优化。
```
