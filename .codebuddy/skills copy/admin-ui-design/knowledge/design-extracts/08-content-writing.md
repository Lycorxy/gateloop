# 08 — 设计中的文案写作

> 来源：frontend-design §Writing + taste-skill §4.9-4.10

## 文案原则

文案是设计材料，不是装饰。像对待间距和色彩一样有意地对待文案。

1. **从用户侧写** — 用人们控制和识别的东西命名，不按系统构建方式
2. **具体优于聪明** — 用通俗语言描述功能，不推销
3. **主动语态** — "保存更改"不是"提交"
4. **全文一致性** — "发布"按钮产生"已发布"toast
5. **一个注册表** — 不混用技术单声道、社评散文、营销 punch

## 发货前文案自审

重新通读页面上每个可见字符串。标记：

- **语法错误**
- **指代不明**
- **AI 幻觉感** — 可爱但不真实的词藻、强行隐喻
- **LLM 伪装深刻** — 被动/攻击型谦逊、伪工匠标签

改写每一个被标记的字符串。不确定 = 替换为简单功能句。AI 生成的可爱文案比无聊文案更糟糕。

## 数字规则

数字如 `92%`、`4.1×`、`48k` 要么来自真实数据，要么明确标注 `<!-- mock -->`。禁止 AI 发明的假精确数字。

## 引用/证言

- 最多 3 行引用正文
- 归属：姓名 + 角色 + (可选)公司。禁止仅写姓名
- 引号用真正的印刷引号 ""，不用 ASCII "

## 错误和空白

- 错误：解释发生了什么，如何修复。用界面声音，不道歉。永远不模糊
- 空白：是一个行动的邀请。设计过的 empty state 指示如何填充

## AI 文案禁用词（绝对禁止）

Elevate、Seamless、Unleash、Next-Gen、Game-changer、Delve、Tapestry、"In the world of..."
