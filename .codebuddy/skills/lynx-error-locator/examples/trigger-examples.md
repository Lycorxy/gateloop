# 触发示例（正向 + 负向）

## 正向（必须触发）

1. `@C:\...\Temp\...\lynx-data-1787560089871.json 这个错误收集的就是这个` —— 拖拽/引用了 lynx-data 导出文件 + 上下文指向错误收集 → 触发
2. `页面报错了，我导出了一份录制数据 lynx-recording-xxx.json，帮我分析下错误在哪，定位到代码位置` —— 导出数据 + 分析错误 + 定位代码 → 触发
3. `分析这个 json 里的报错，一堆资源加载失败，找下是什么原因，出问题的代码在哪` —— 分析 json 报错 + 定位原因与代码 → 触发

## 负向（不得触发）

1. `帮我修复这个报错：Cannot read properties of undefined` —— 用户贴的是错误文本且要求直接修复 → 不触发（修复属后续流程；无导出 JSON 数据）
2. `把这份 lynx-data-xxx.json 回放一下，看看用户操作轨迹` —— 仅要求回放/查看，无错误分析诉求 → 不触发
3. `用这份 json 数据写个解析器` —— 数据被当作开发素材，不是错误定位 → 不触发

## 边界（触发但走特殊路径）

- `这份 lynx-data.json 里没看到报错，但用户反馈页面很卡，帮我看看` —— 有导出数据 + 性能问题诉求 → 触发，走 noErrors 路径（masterPrompt 聚焦用户描述的卡顿现象，按 performance/memory 战术分析）
