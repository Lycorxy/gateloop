# 需求文档输出模板

> 来自 Step 5.1 结构化需求文档。SKILL.md 引用此模板，执行时填入实际内容。

```markdown
# 需求文档：[需求名称]

> 版本：v1.0 | 日期：{日期} | 作者：AI 辅助生成 | 状态：待评审

## 1. 概述

### 1.1 一句话描述

{一句话说明这个需求要解决什么问题}

### 1.2 目标用户

- **主要用户**：{角色描述} — {核心场景}
- **次要用户**：{角色描述} — {使用场景}

### 1.3 当前痛点

{用户现在怎么做的？有什么问题？}

## 2. 需求详情

### 2.1 核心场景（Given-When-Then）

{3-5 个关键场景}

### 2.2 功能列表（MoSCoW）

🔴 Must Have: ...
🟡 Should Have: ...
🟢 Could Have: ...
⚪ Won't Have: ...

### 2.3 交互流程

{关键操作步骤，必要时用流程图}

## 3. 验收标准

### 3.1 功能验收

- [ ] {可测试的验收条件1}
- [ ] {可测试的验收条件2}

### 3.2 非功能验收

- [ ] 性能：{指标}
- [ ] 安全：{要求}
- [ ] 兼容：{要求}

## 4. 边界与约束

### 4.1 范围内

- {明确在范围内的}

### 4.2 范围外（暂不做）

- {明确排除的} — 理由：{为什么}

### 4.3 依赖

- {依赖项} → {状态}

## 5. 风险与假设

### 5.1 关键假设

| 假设 | 验证方式 | 如果错了怎么办 |
|------|---------|---------------|
| {假设1} | {方式} | {降级方案} |

### 5.2 已识别风险

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|---------|
| {风险1} | 高/中/低 | 高/中/低 | {措施} |

## 6. 价值评估

| 维度 | 评分 | 说明 |
|------|------|------|
| 用户痛点 | ?/5 | |
| 影响范围 | ?/5 | |
| 使用频率 | ?/5 | |
| 商业价值 | ?/5 | |
| 战略契合 | ?/5 | |
| **综合** | **?/25** | |
```
