## 一、布局决策树

```
用户想做什么？
│
├─ 浏览数据列表 → 【标准列表页】(§二)
│
├─ 查看/编辑单条记录
│   ├─ 字段 ≤ 6   → 【Modal 编辑】(宽 520px)
│   ├─ 字段 7-15  → 【Drawer 编辑】(右滑入，宽 640px)
│   └─ 字段 > 15  → 【独立详情页】(居中卡片 max-width: 960px)
│
├─ 监控数据趋势 → 【数据看板】(§三)
│
├─ 配置系统设置 → 【设置页】(§四)
│
└─ 快速查找/执行 → 【Command Palette】(Cmd+K)
```

### 空间效率优化技巧

| 技巧 | 说明 | 适用场景 |
|------|------|---------|
| **可折叠搜索区** | 默认展开，点击"收起"只保留一行 | 筛选项 ≥ 4 个时 |
| **表格行 hover 操作** | 操作按钮默认隐藏，hover 行时右侧浮现 | 操作 ≥ 2 个时 |
| **列固定** | 前 N 列 + 操作列 sticky | 列数 ≥ 6 时 |
| **虚拟滚动** | 只渲染可视区域行 | 数据量 ≥ 500 条时 |
| **行内编辑** | 点击单元格直接编辑 | 简单字段修改 |
| **密度切换** | 舒适/紧凑/超密三档 | 用户偏好 |

```
┌──────────────────────────────────────────────────────────┐
│  数据概览                                                  │
│  ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐                     │
│  │ 1,234│ │  567 │ │ 89%  │ │  12  │  ← KPI Strip        │
│  │总用户 │ │活跃数 │ │转化率 │ │待处理 │                     │
│  └──────┘ └──────┘ └──────┘ └──────┘                     │
│                                                          │
│  ┌─ 图表区域（左右分栏）──────────┐ ┌─ 排行榜 ────────┐   │
│  │                               │ │                │   │
│  │     (折线图/柱状图)             │ │ 1. xxxxx       │   │
│  │                               │ │ 2. xxxxx       │   │
│  │                               │ │ 3. xxxxx       │   │
│  └───────────────────────────────┘ └────────────────┘   │
└──────────────────────────────────────────────────────────┘
```

### Dashboard 设计原则

1. **一个仪表盘 = 一个决策**（CEO 看营收，运维看告警，不要混在一起）
2. **3-5 个 Hero Metrics**（不能再多）
3. **F 排序**：最重要的数字在左上角
4. **图表解释 KPI**（不要放无关图表）
5. **表格放最下面**（用于钻取明细）

### Dashboard 类型

| 类型 | 用途 | 特点 |
|------|------|------|
| **Operational** | 实时监控 | 实时数据、告警、快速决策 |
| **Strategic** | 长期决策 | KPI 鸟瞰、跨部门数据、回溯对比 |
| **Analytical** | 深度分析 | 多维切片、钻取、复杂交互 |

### 真实案例：TextMagic CRM Dashboard

```
来源：Eleken 设计案例

- 清晰的视觉层次
- 条形图适合跨类别比较
- 颜色编码引导用户注意力

Takeaway：
✅ 用不同图表展示不同类型数据
✅ 多 Tab 清理屏幕
✅ 清晰视觉层次
✅ 条形图适合跨类别比较
✅ 颜色编码引导注意力
```

### 设置页最佳实践（来源：0xMinds）

```
- Tab 导航与 URL 同步（刷新不丢失位置）
- 未保存变更提示（离开前警告）
- 保存成功 Toast 通知
- 每个设置区域用卡片分组
- 开关/Select 代替复杂表单
```

## 五、侧边栏设计

### 0xMinds 最佳实践

```
侧边栏是最重要的导航组件，决定 50% 的可用性。

结构：
┌──────────────────┐
│ [Logo] 产品名     │  ← h:56px
├──────────────────┤
│ 🔍 搜索...       │  ← 全局搜索入口
├──────────────────┤
│ ▸ 仪表盘         │  ← 导航项
│ ▸ 项目管理       │
│   ├─ 项目列表     │  ← 子菜单
│   └─ 项目配置     │
│ ▸ 用户中心       │
│ ▸ 系统设置       │
├──────────────────┤
│ 👤 管理员        │  ← 底部用户区
│    退出登录       │
└──────────────────┘

规则：
- 宽度：240px（展开）/ 64px（收起仅图标）
- 导航项高度：40px
- 激活态：bg blue-02 + text blue-07
- 子菜单缩进：padding-left + 8px
- 收起态：Tooltip 显示完整名称
```

## 六、响应式断点

| 断点 | 宽度 | 布局变化 |
|------|------|---------|
| **xl** | ≥ 1920px | 侧边栏展开 + 内容区 max-width |
| **lg** | ≥ 1440px | 标准布局 |
| **md** | ≥ 1200px | 侧边栏可收起 |
| **sm** | ≥ 768px | 侧边栏隐藏，汉堡菜单 |
| **xs** | < 768px | 全部单列，表格转卡片 |
