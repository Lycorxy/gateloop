# 场景穷举模式与模板

用 Given-When-Then 格式穷举所有场景。**必须覆盖 5 类场景**，缺一类则需求不完整。

## 1. 正常场景（Happy Path）

> 一切顺利时，用户的理想路径。

```gherkin
给定 {前置条件：用户已登录、有权限、数据存在}
当   {用户执行核心操作}
则   {系统返回预期结果}

示例：
给定 用户已登录且有"导出报表"权限
当   用户选择日期范围并点击"导出"
则   系统生成Excel文件并触发下载
```

## 2. 边界场景（Edge Cases）

> 极端输入、极限条件、数据边界。

```gherkin
给定 用户输入了{极端值/空值/超长值/特殊字符}
当   用户提交
则   系统{给出明确提示 / 阻止提交 / 正常处理}

示例（至少覆盖 3 个边界）：
- 空输入：所有必填字段为空时提交
- 最大输入：文本输入超最大长度（如10000字）
- 最小输入：只输入一个字符/一条数据
- 特殊字符：输入 emoji / SQL 注入字符 / HTML 标签
- 日期边界：选择 1900-01-01 或 2099-12-31
- 数值边界：输入 0 / 负数 / 极大值（如 9999999999）
```

## 3. 异常场景（Error Cases）

> 外部依赖不可用时的系统表现。

```gherkin
给定 {外部依赖异常}
当   用户{执行操作}
则   系统{优雅降级 + 明确提示 + 数据不丢失}

示例（至少覆盖 3 个异常）：
- 网络中断：操作中途断网 → 已填写数据保留，恢复后可继续
- 服务超时：后端响应超时（如30秒）→ 提示"操作超时，请重试"
- 服务不可用：后端返回 500 → 提示"系统繁忙，请稍后重试"，非技术错误码
- 第三方依赖失败：支付/短信/OAuth 失败 → 明确告知用户并允许重试
- 数据不可用：查询的数据已被删除 → 提示"数据不存在或已被删除"
```

## 4. 并发场景

> 多人/多设备同时操作时的数据一致性。

```gherkin
示例（至少覆盖 2 个场景）：
- 编辑冲突：
  给定 用户A和用户B同时打开同一数据编辑
  当   用户A先保存，用户B后保存
  则   用户B收到"数据已被他人修改"提示，可选择覆盖或放弃

- 并发创建：
  给定 两个用户同时创建同名资源
  当   双方都提交
  则   先提交者成功，后提交者收到"名称已存在"提示

- 重复提交：
  给定 用户快速双击提交按钮
  当   两次请求到达服务器
  则   只处理一次（幂等性），第二次返回"请勿重复操作"
```

## 5. 权限场景

> 不同角色、不同权限下的访问控制。

```gherkin
示例（至少覆盖 2 个场景）：
- 无权限访问：
  给定 用户角色为"普通用户"（无管理权限）
  当   用户访问管理后台URL
  则   返回 403 或重定向到首页 + 提示"无权访问"

- 越权操作：
  给定 用户A只能查看自己的数据
  当   用户A通过修改URL参数尝试查看用户B的数据
  则   系统返回"无权查看"或空结果

- 权限变更：
  给定 用户正在编辑，管理员撤销了其编辑权限
  当   用户提交编辑
  则   提示"权限已变更，请刷新页面"
```

## 使用指南

1. 每个需求至少覆盖全部 5 类场景
2. 每类场景至少写 2 个具体例子
3. 用业务语言描述，避免技术术语
4. 场景描述应让非技术人员也能理解
5. 特别关注"用户输入不可控"的场景（用户可能输入任何东西）

## 常见遗漏场景速查

```
□ 首次使用（无历史数据）
□ 数据为空（列表无数据时显示什么）
□ 数据极多（1万+条时的分页/性能）
□ 浏览器后退按钮
□ 页面刷新（编辑到一半按F5）
□ 多标签页（两个标签页同时操作）
□ 移动端（小屏幕下的布局和操作）
□ 弱网环境（2G/3G下的体验）
□ 辅助功能（屏幕阅读器/键盘导航）
□ 国际化（多语言下的UI文案长度）
```
