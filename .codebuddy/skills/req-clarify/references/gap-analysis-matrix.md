# 差距分析矩阵

> Step 3 差距分析时加载。包含需求合理性判断表、差距检测矩阵、差距报告格式。

---

## 1. 需求合理性判断（8 维度）

> 不只是找漏洞，还要判断用户的需求本身是否合理。基于代码事实和项目现状判断方向是否正确。

| 判断维度 | 检测问题 | 判定标准 |
|----------|---------|---------|
| **方向正确性** | 用户要解决的问题是否是真正的问题？ | 基于代码现状分析，是否已有更好的替代方案？ |
| **范围合理性** | 需求范围是否过大/过小？ | 对比现有模块复杂度，是否超出合理边界？ |
| **技术可行性** | 需求与现有架构是否兼容？ | 是否需要引入新技术栈？是否与现有模式冲突？ |
| **数据合理性** | 用户描述的数据流转是否正确？ | 与现有数据模型对比，字段/类型/关系是否匹配？ |
| **交互合理性** | 用户设想的操作流程是否合理？ | 是否有更短路径？是否符合用户习惯？ |
| **布局合理性** | 用户期望的页面结构是否合适？ | 与同类现有页面对比，是否一致？信息密度是否合理？ |
| **路由合理性** | 路由设计是否合理？ | 是否与现有路由体系融合？参数设计是否规范？ |
| **体验合理性** | 用户体验目标是否可实现？ | 与现有交互模式对比，是否过度设计或不足？ |

**合理性判断输出格式：**

```
📐 需求合理性判断：

方向正确性: ✅ 合理 / ⚠️ {偏差说明} / ❌ {方向错误，建议改为{替代方案}}
范围合理性: ✅ 合理 / ⚠️ {过大/过小说明} / ❌ {需要拆分/扩展}
技术可行性: ✅ 可行 / ⚠️ {风险点} / ❌ {不可行，原因{X}}
数据合理性: ✅ 正确 / ⚠️ {字段不匹配} / ❌ {数据模型错误}
交互合理性: ✅ 合理 / ⚠️ {可优化} / ❌ {操作路径不合理}
布局合理性: ✅ 合适 / ⚠️ {密度问题} / ❌ {页面类型选择错误}
路由合理性: ✅ 合理 / ⚠️ {参数设计} / ❌ {路由冲突}
体验合理性: ✅ 可实现 / ⚠️ {过度设计/不足} / ❌ {目标不现实}
```

## 2. 差距检测矩阵（10 类）

| 检测项 | 检测方法 | 漏洞示例 |
|--------|---------|---------|
| **功能缺失** | 需求功能点 vs 现有功能 | "需要导出但项目没有导出模块" |
| **数据断裂** | 数据流转链路完整性 | "前端需要字段X但后端API不返回" |
| **接口缺失** | 需要的接口 vs 已有接口 | "需要批量删除但只有单条删除接口" |
| **状态管理缺失** | 跨页面数据共享需求 | "需要跨页面传递选中数据但没有对应store" |
| **权限漏洞** | 操作权限 vs 现有权限体系 | "新增页面但没有配置角色权限" |
| **边界遗漏** | 用户描述中缺失的边界 | "用户没提空数据展示但列表必须有空态" |
| **交互缺失** | 操作反馈完整性 | "提交后没有loading态/成功提示" |
| **体验缺失** | 用户体验维度遗漏 | "高频操作步骤过多，缺少快捷操作" |
| **样式规范缺失** | 设计规范一致性 | "新页面没有遵循现有卡片三件套规范" |
| **路由冲突** | 新路由 vs 已有路由 | "新路由path与已有路由重叠" |

## 3. 差距报告输出格式

```
🔍 差距分析报告

【功能缺失】(N项)
  ⚠️ 缺失: {描述} — 影响: {高/中/低} — 建议: {补齐方案}

【数据断裂】(N项)
  ⚠️ 断裂: {字段X在前端需要但后端未返回} — 建议: {后端补充字段 / 前端transform}

【接口缺失】(N项)
  ⚠️ 缺失: {接口名} — 建议: {新增 / 复用改造}

【边界遗漏】(N项)
  ⚠️ 遗漏: {空数据/并发/权限/网络异常} — 建议: {补充处理}

【交互缺失】(N项)
  ⚠️ 缺失: {loading/success/error反馈} — 建议: {补充状态}

【体验缺失】(N项)
  ⚠️ 缺失: {操作过长/缺快捷方式/反馈不及时} — 建议: {优化方案}

【其他】(N项)
  ⚠️ {类型}: {描述} — 建议: {方案}
```
