# 触发示例

## 正向触发（必须触发）

### 示例 1
```
用户：帮我优化这个 figma 节点的还原度 https://www.figma.com/design/RUaAbbQdi2ElguDRW9zHrl/xxx?node-id=2094-77836&m=dev
```
触发原因：明确要求"优化还原度" + 提供了 Figma URL

### 示例 2
```
用户：这个 DSL 的还原度只有 72%，帮我迭代优化到 95% 以上
```
触发原因：明确要求"迭代优化" + 目标"95%"

### 示例 3
```
用户：对比一下原版和优化后的图，差异大的地方继续优化
```
触发原因：明确要求"对比" + "继续优化"

### 示例 4
```
用户：figma还原优化，这个页面布局不太对，帮我用 flex 重新优化
```
触发原因：明确"figma还原优化" + "flex 重新优化"

### 示例 5
```
用户：上次的优化还没到 95%，继续优化还原
```
触发原因："继续优化还原"，恢复中断的优化流程

---

## 负向触发（必须不触发）

### 反例 1
```
用户：帮我把这个 figma 链接转成 DSL
```
不触发原因：只要求转换，不要求优化迭代 → 直接用 figma_to_dsl 工具

### 反例 2
```
用户：对比这两张图片的差异
```
不触发原因：非 Figma 场景的图片对比 → 直接用 compare_images 工具

### 反例 3
```
用户：帮我审查这段 CSS 代码有什么问题
```
不触发原因：纯代码审查，与 Figma 还原无关

### 反例 4
```
用户：帮我设计一个新的管理后台页面
```
不触发原因：不是还原优化，是全新设计 → 用 admin-ui-design skill

### 反例 5
```
用户：这个 HTML 渲染出来有 bug，帮我修一下
```
不触发原因：是修 bug，不是优化还原度 → 用 fix 流程
