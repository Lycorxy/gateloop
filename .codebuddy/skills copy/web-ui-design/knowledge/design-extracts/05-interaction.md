# 05 — 交互哲学

---

## 一、交互设计的核心追求

> 最好的交互是用户意识不到交互的存在。操作自然、反馈即时、路径直觉。

### 三个层次

| 层次 | 标准 | 代表产品 |
|------|------|---------|
| **功能可用** | 能完成任务 | 大部分产品 |
| **高效好用** | 最少步骤完成 | Linear, Stripe |
| **愉悦享用** | 操作有成就感 | Notion, Figma |

## 二、操作效率分析法

### 操作成本计算

每个操作都有成本，用户会无意识地评估：

| 操作类型 | 成本 | 示例 |
|---------|------|------|
| 视觉扫描 | 低 | 找到目标位置 |
| 鼠标移动 | 低-中 | Fitts' Law（距离/大小） |
| 点击 | 中 | 单次点击 |
| 双击/右键 | 中-高 | 不够直觉 |
| 键盘输入 | 中 | 搜索/填写 |
| 认知判断 | 高 | "这个按钮是做什么的？" |
| 等待 | 高 | Loading（每 100ms 都在流失） |
| 页面跳转 | 很高 | 丢失上下文 |

### Fitts' Law 应用

```
到达目标的时间 ∝ 距离 / 目标大小

设计启示：
1. 常用按钮放在容易到达的位置（不要角落）
2. 重要按钮适当大一些（≥ 36px 高度）
3. 相关操作聚集在一起（减少移动距离）
4. 边缘/角落有无限大的"虚拟目标"（利用屏幕边缘）
```

## 四、信息展示策略

### 渐进式披露层级

```
┌─ Always Visible ──────────────────────────────┐
│  P0: 标题、状态、核心 KPI                      │
│  → 用户一眼就能看到最重要的信息                │
├─ On Hover ────────────────────────────────────┤
│  P1: 操作按钮、补充数据、快速预览              │
│  → 鼠标悬停时展示，不占常态空间                │
├─ On Click (1 step) ──────────────────────────┤
│  P1.5: Tab 内容、Dropdown 选项、展开详情       │
│  → 1 次点击可达                                │
├─ On Navigate (2+ steps) ─────────────────────┤
│  P2-P3: 详情页面、设置选项、历史记录           │
│  → 需要跳转或多步操作                          │
└───────────────────────────────────────────────┘
```

### 何时隐藏信息

| 隐藏条件 | 隐藏方式 | 触发方式 |
|---------|---------|---------|
| 使用频率 < 20% | Collapse/More | Click 展开 |
| 仅特定角色需要 | 权限控制/Tab | Tab 切换 |
| 辅助性质 | Tooltip/Small text | Hover 触达 |
| 上下文不需要 | 条件渲染 | 依赖条件满足 |
| 空间不够 | Drawer/Modal | Click 打开 |

## 五、微交互设计

### 按钮状态流转

```
Default → [hover] → Hover → [press] → Active → [release] → Default
    ↓                                                ↓
  [focus]                                        [成功/失败]
    ↓                                                ↓
  Focus                                         反馈态(闪烁/变色)
                                                     ↓
                                                  恢复 Default
```

### Hover 信息设计

```
行 hover 可以展示：
1. 操作按钮（编辑/删除/更多）
2. 快速预览（Tooltip 摘要）
3. 视觉高亮（背景变化）

行 hover 不应该：
1. 改变布局（元素位移）
2. 展示大量新内容
3. 触发网络请求
4. 有延迟（hover 反馈应 < 120ms）
```

## 六、操作确认策略

### 什么操作需要确认

| 操作性质 | 是否确认 | 方式 |
|---------|---------|------|
| 不可逆（删除） | ✅ 必须 | Modal + 输入确认 |
| 影响范围大（批量） | ✅ 必须 | Modal + 数量提示 |
| 可逆但有成本（发布） | ⚠️ 可选 | Popover 确认 |
| 轻量可逆（标记/移动） | ❌ 不需要 | 直接执行 + Undo |
| 日常操作（保存/切换） | ❌ 不需要 | 直接执行 |

### Undo 优于 Confirm

```
优先使用 "直接操作 + Undo Toast"：
1. 用户操作立即生效（Optimistic UI）
2. 底部/右下出现 "已删除 XXX [撤销]" Toast
3. 3-5s 后消失 → 真正执行
4. 用户点撤销 → 恢复

这比 "你确定要删除吗？[确定][取消]" 体验好 100 倍。

仅在以下情况使用 Confirm Modal：
- 操作真的不可逆（无法 undo）
- 操作涉及金钱/权限/数据丢失
```

## 七、键盘交互

### 专业工具必须支持

| 功能 | 快捷键 | 场景 |
|------|--------|------|
| 全局搜索 | Cmd/Ctrl + K | 命令面板 |
| 保存 | Cmd/Ctrl + S | 编辑页面 |
| 新建 | Cmd/Ctrl + N | 列表页 |
| 删除 | Delete/Backspace | 选中后删除 |
| 取消/关闭 | Esc | 弹窗/编辑态 |
| 提交 | Enter | 表单/搜索 |
| 导航 | ↑↓ | 列表/菜单 |
| 选择 | Space | 复选框/选项 |

### 焦点管理

```
Tab 顺序必须符合逻辑：
标题 → 搜索框 → 筛选 → 表格行 → 分页 → 操作按钮

Modal 打开时：
1. Focus trap（焦点锁定在 Modal 内）
2. 关闭后焦点回到触发元素
3. Esc 关闭
```
