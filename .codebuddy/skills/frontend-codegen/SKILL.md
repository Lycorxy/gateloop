# Frontend Codegen v7.2 — 前端代码生成（唯一入口）

## 🛑 入口守卫（最高优先级·不可绕过）

```
本 Skill 被 use_skill 加载后，必须按顺序执行 Step 0→1→2→3→5→6 全部 6 步。
每步必须播报对应完成消息。未播报的步骤 = 未执行 = 违规。

禁止行为：
  ✗ 加载 Skill 后跳过 Step 0 直接写代码
  ✗ 用 read_lints 替代 Step 5/6 的 npx nut-lint fix + npx nut-lint run
  ✗ 跳过 Step 2 us_skill("eslint-code-quality")
  ✗ 跳过 Step 3 任务类型判定表
  ✗ 不播报完成消息（无日志 = 没走流程）

唯一例外：同会话已执行并播报过的步骤可跳过，但必须声明：
  ⏭️ [跳过] Step N — 原因 | 风险
```

**核心定位：不是"写前端代码"，而是"像一个前端架构师那样，先检测环境、再判定路径、委派专家、最后验证交付"。**

> 🧠 **设计哲学**：作为唯一入口，像一个经验丰富的技术组长那样——先确认项目规范，
> 再判断任务该交给谁做（样式专家/联调专家/自己动手），最后验收交付。
> 每一步都有约束，每一步都有播报，不通过不继续。
> **注**：前端架构设计由独立的 `frontend-design` Skill 在上游阶段完成，不在本 Skill 流程内。

核心目标排序：**路径正确 > 规则合规 > 代码质量 > 验证通过**

---

## 何时使用 / 何时不使用

**应该触发：**

- 任何前端代码生成/修改任务
- 新建组件、修改组件、写页面
- 写样式、联调接口
- 其他 Skill（specflow-dev, specflow-fix）需要生成前端代码时

**不应触发：**

- 纯后端开发 / 数据库设计
- 非 Web 前端（移动端原生 / 桌面端）
- 前端架构设计 / 技术方案设计 → `frontend-design`（独立的上游阶段）

## 中断与恢复机制

若执行过程被中断（如模型输出截断），重新继续时必须：

1. **扫描已有输出** — 检查已完成的 Step 及其完成播报
2. **播报恢复点**：
   ```
   ⏯️ [恢复] 上次进度：X/6 步完成
   已完成：✅ Step 0 — 规则注入
           ✅ Step 1 — 环境检测
           ✅ Step 2 — Lint 规则
           ✅ Step 3 — 任务判定
           ✅ Step 4 — 编码
           ✅ Step 5 — 格式化验证
           ✅ Step 6 — 全量验证
   待完成：⬜ Step N — {待完成步骤}
   断点：从 Step N 继续
   ```
3. **从断点继续** — 不重复已完成步骤，不遗漏未完成步骤
4. **重启确认** — 播报恢复后主动询问用户是否继续

## Step 1 — 项目环境检测 [低自由度 · 强制]

```
【🔒 不可变约束】
  Step 1 必须在任何代码生成之前完成。
  未进行项目环境检测就开始写代码 = 严重违规，代码风格/API 用法可能不匹配项目。
```

### 1.1 并行读取项目配置

```typescript
read_file('package.json') // JSX Runtime, React版本, UI库, 样式方案, lint工具
read_file('tsconfig.json') // strict, paths, jsxImportSource, module
read_file('.eslintrc.cjs') // ESLint 规则集
read_file('.prettierrc') // 格式化规则
read_file('.stylelintrc.cjs') // 样式 lint 规则（★ 样式任务必需）
```

### 1.2 环境检测清单（强制逐条检查）

```
□ JSX 运行时
    - "react-jsx" → automatic（无需 import React）
    - "react" / 未设置 → classic（必须 import React）

□ TypeScript 严格模式
    - true  → 禁止 any
    - false → 谨慎使用 any

□ 路径别名
    - { "@/*": ["src/*"] } → import 用 @/ 别名
    - 无 → 全部用相对路径

□ 模块系统
    - "type": "module" + ESNext → ESM
    - 无 type + CommonJS → CJS

□ UI 库
    - antd → antd 组件 API
    - @mui → MUI 组件 API
    - 无 → 纯自定义组件

□ 样式方案（★ 判定是否委派 css-style-writer）
    - CSS Module 存在 → 走 css-style-writer
    - tailwind.config.* 存在 → 直接写 className
    - styled-components / emotion → CSS-in-JS

□ 后端联调状态（★ 判定是否委派 frontend-backend-integration）
    - 用户提到"联调/接口/mock替换" → 走联调
    - 项目有 mock 数据 → 可能需要联调
    - 纯前端 → 不走联调
```

> 完成播报：`"✅ Step 1 环境检测完成：{JSX}/{TS}/{路径别名}/{UI库}/{样式方案}"` — 未播报不得进入 Step 2。
>
> **验证检查点：**
> ```
> □ JSX运行时 / TS严格 / 路径别名 / 模块系统 均已检测
> □ UI库 / 样式方案 / 联调状态 均已确认
> □ 检测结果已决定后续代码生成策略
> ```
>
> 🔒 **强制约束**：此步骤不可跳过。不检测就编码 = 可能违反项目规范。

## Step 3 — ★ 任务类型判定 & 委派执行 [低自由度 · 强制]

```
【🔒 不可变约束】
  本步骤决定后续所有代码生成的执行路径。
  禁止跳过判定直接写代码。
  禁止同时走两条路径导致冲突。
```

### 3.1 任务类型矩阵

| #   | 任务类型             | 判定条件                                | 委派目标                                     |
| --- | -------------------- | --------------------------------------- | -------------------------------------------- |
| A   | **纯样式**           | 创建/修改 `.scss`/`.css`/`.module.scss` | → `css-style-writer`                         |
| B   | **前后端联调**       | mock 替换、接口对接                     | → `frontend-backend-integration`             |
| C   | **组件代码(含样式)** | 新建组件（TSX+TS+SCSS 三文件）          | → 先当前Skill(逻辑) + css-style-writer(样式) |
| D   | **纯逻辑/组件**      | 只写 TSX/TS/Hook；无样式变更            | → 当前 Skill 直接执行                        |
| E   | **联调+样式**        | 联调含UI调整                            | → 先 B 再 A                                  |

### 3.2 委派执行流程

```
路径 A: 纯样式 → use_skill("css-style-writer") → 完成
路径 B: 联调   → use_skill("frontend-backend-integration") → 完成
路径 C: 组件   → 当前Skill写逻辑 → use_skill("css-style-writer")写样式 → 完成
路径 D: 纯逻辑 → 当前Skill直接执行 → 完成
路径 E: 联调+样式 → 先 B → 再 A → 完成
```

### 3.3 委派注意事项

```
★ 规则去重：specflow-rules-engine 由 Step 0 统一加载，子 Skill 会自动检测
★ 顺序约束：联调优先于样式（路径E），先保证数据正确再调 UI
★ 禁止：在委派 css-style-writer 时自行写样式 / 在委派联调时自行改数据层
```

### 3.4 🔒 强制委派验证（核心机制 · 不可跳过）

> **这是确保委派真正执行的关键机制。** 没有它，模型可能跳过 `use_skill` 调用而自行处理。

#### 3.4.1 委派判定表（必须填写并播报）

在判定任务类型后，**必须**输出以下判定表：

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📋 任务类型判定：路径 {A/B/C/D/E}
  任务描述：{用户具体要做什么}
  委派目标：{Skill 名称 或 "当前Skill"}
  委派范围：{委派给子Skill做什么，当前Skill保留做什么}
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

**示例**：

```
📋 任务类型判定：路径 C
  任务描述：新建用户管理列表页（含表格+搜索+样式）
  委派目标：css-style-writer
  委派范围：样式部分（index.module.scss）→ css-style-writer
           逻辑部分（index.tsx + hook.ts）→ 当前Skill
```

#### 3.4.2 委派执行验证（强制检查）

委派后**必须**确认 `use_skill()` 调用已执行且成功：

```
【🔒 委派执行验证清单（不可跳过）】
□ use_skill() 已调用（不是口头说委派，而是真的调用了）
□ use_skill() 返回成功（子Skill已接管对应领域）
□ 当前Skill不再自行处理被委派领域的代码
```

**违规示例**：

- ❌ 判定走路径A（纯样式→css-style-writer），但实际自己写了SCSS代码而没有调用 `use_skill("css-style-writer")`
- ❌ 判定走路径C（组件含样式），写了TSX逻辑后，自己又写了SCSS代码，没有委派给 css-style-writer
- ❌ 判定走路径B（联调→frontend-backend-integration），但自己改了数据层代码而没有调用 `use_skill("frontend-backend-integration")`

**正确示例**：

- ✅ 判定路径A → 输出判定表 → 调用 `use_skill("css-style-writer")` → 确认子Skill接管 → 当前Skill不再写样式
- ✅ 判定路径C → 输出判定表 → 当前Skill写TSX/TS逻辑 → 调用 `use_skill("css-style-writer")` 写SCSS → 确认子Skill接管样式
- ✅ 判定路径D → 输出判定表 → 当前Skill直接执行所有代码 → 无需委派

#### 3.4.3 委派冲突检测

```
⚠️ 冲突信号（出现任一即停）：
  - 当前Skill写了样式代码，但判定路径是A/C（样式应委派）
  - 当前Skill改了数据层，但判定路径是B/E（联调应委派）
  - 同时调用了两个子Skill（路径冲突）
  - 委派后仍在处理被委派领域的代码（越权）

冲突处理：
  1. 立即停止当前操作
  2. 回退到 Step 3 重新判定
  3. 明确划分当前Skill vs 子Skill的职责边界
```

> 完成播报：`"✅ Step 3 任务执行完成：路径{X} / 委派{目标}"` — 必须包含判定表内容。
>
> **验证检查点：**
> ```
> □ 委派判定表已输出
> □ 判定路径正确（A/B/C/D/E）
> □ 需委派时 use_skill() 已调用且成功
> □ 当前Skill未越权处理被委派领域
> ```
>
>
> 🔒 **强制约束**：此步骤不可跳过。禁止跳过判定直接写代码。禁止跳过委派验证。
>
> ⏭️ **可跳过条件**：仅限路径 D（纯逻辑，无需委派），且必须声明：
> `⏭️ [跳过] Step 3 委派验证 | 理由：路径D纯逻辑，无需委派 | 风险：无`

## Step 4 — 编码规范（仅路径 C/D/E 的逻辑部分）[低自由度]

### 4.1 三文件模式

```
index.tsx           ≤ 120 行（纯 JSX + 组件组合）
hook.ts             ≤ 150 行（状态管理 + 副作用）
index.module.scss   ≤ 200 行（★ 由 css-style-writer 负责）
```

### 4.2 TypeScript 强约束

```
- 禁止 any，必须定义接口/类型
- async 函数禁止直接传 onClick → 用 () => { void fn(); }
- 简单类型 T[]，复杂类型 Array<T>
- try/catch 的 err 必须 instanceof Error 类型守卫
```

### 4.3 Import 顺序

```
1. 第三方库（antd, react）— 字母序
2. 项目内部模块（@/ 别名）
3. 相对路径模块（./）
4. 样式文件（.scss）— 最后
```

> 🔒 **强制约束**：若走路径 A/B，此步骤跳过（由委派 Skill 负责）。
> 跳过声明：`⏭️ [跳过] Step 4 编码规范 | 理由：路径A/B，逻辑由委派Skill处理 | 风险：无`

## 错误处理

| 场景                 | 处理方式                                                          |
| -------------------- | ----------------------------------------------------------------- |
| 任务类型无法判定     | 询问用户："这次改动主要涉及哪方面？A.样式 B.联调 C.都有 D.纯逻辑" |
| 委派的 Skill 报错    | 将错误原样上报用户，附上建议修复方向                              |
| 规则冲突             | 按路径 E 顺序执行，后者覆盖前者（需确认）                         |
| 用户中途切换任务类型 | 重新执行 Step 3 判定                                              |
