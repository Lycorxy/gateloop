# 交互模式详解

---

## 一、交互设计核心原则

### 渐进式披露（Progressive Disclosure）

```
Level 0: 默认展示 → 核心信息 + 主操作（P0）
Level 1: Hover/Focus → 次要操作、补充信息（P1）
Level 2: Click/展开 → 详细内容、设置选项（P2）
Level 3: Modal/新页 → 完整流程、复杂表单（P3）
```

**原则**：永远先展示最少的信息，让用户按需深入。

### 格式塔原则在交互中的应用

| 原则 | 交互设计应用 |
|------|-------------|
| **亲密性** | 相关操作物理距离近，用间距分组 |
| **相似性** | 同类操作样式一致（同色/同尺寸） |
| **连续性** | 操作流程有清晰的视觉引导路径 |
| **闭合性** | 操作有明确的开始和结束反馈 |
| **图底关系** | 当前焦点突出，背景淡化 |

## 二、交互方案选择矩阵

### Tab vs Select vs Segmented

| 因素 | Tab | Select | Segmented |
|------|-----|--------|-----------|
| **最佳选项数** | 2-5 | 5-20 | 2-4 |
| **点击次数** | 1 | 2（展开+选择） | 1 |
| **空间占用** | 横向 | 极小（固定宽） | 横向（紧凑） |
| **选项可见性** | 全部可见 | 当前选项可见 | 全部可见 |
| **切换频率** | 高频 | 低频 | 中高频 |
| **内容关系** | 平级 Tab 内容 | 筛选/配置项 | 视图模式切换 |
| **横向空间** | 需 > 400px | 只需 120px | 需 200-300px |

**决策规则**：
```
选项 ≤ 5 + 高频切换 + 空间够 → Tab
选项 > 5 或空间不够 → Select
选项 ≤ 4 + 模式切换性质 → Segmented
```

### Modal vs Drawer vs Inline vs Popover

| 因素 | Modal | Drawer | Inline | Popover |
|------|-------|--------|--------|---------|
| **内容量** | 少(≤5 字段) | 多(5-20 字段) | 极少(1-2) | 少(提示/确认) |
| **阻断性** | 强阻断 | 弱阻断 | 无阻断 | 弱阻断 |
| **上下文** | 不需要 | 需要参考 | 紧贴上下文 | 需要参考 |
| **操作频率** | 低频 | 中频 | 高频 | 中频 |
| **回退成本** | 点取消 | 点关闭/外部 | 失焦即回退 | 点外部 |
| **适用场景** | 确认/警告/重要 | 编辑/详情/设置 | 即时编辑 | 简单操作/提示 |

**决策规则**：
```
破坏性操作需确认 → Modal
查看/编辑详情 → Drawer（不遮挡列表）
高频单字段修改 → Inline Edit
轻量确认/选择 → Popover
```

### Accordion vs Collapse vs Tab（内容折叠）

| 因素 | Accordion | Collapse | Tab |
|------|-----------|----------|-----|
| **同时可见** | 只 1 个（互斥） | 可多个 | 只 1 个 |
| **内容长度** | 中等（可变高） | 长（可变高） | 固定高度区域 |
| **总量** | 3-10 项 | 不限 | ≤ 5 项 |
| **用户心理** | "我找到对应的了" | "让我看看这些" | "切换视角" |

## 三、操作效率设计

### 高频操作优化策略

| 策略 | 实现方式 | 适用场景 |
|------|---------|---------|
| **快捷键** | Cmd+K 命令面板 | 专业用户/重度使用 |
| **右键菜单** | ContextMenu | 列表项操作 |
| **行内操作** | Hover 出现按钮 | 表格行操作 |
| **批量操作** | 复选 + 顶部操作栏 | 表格批量 |
| **拖拽** | DnD 排序/分组 | 排序/归类 |
| **双击编辑** | Double-click → Input | 快速修改 |

### 操作步骤评估

```
★★★★★ 1步：直接点击/快捷键即完成
★★★★  2步：点击 → 确认/选择
★★★   3步：点击 → 填写 → 确认
★★    4步：开始感到繁琐
★     5步+：需要优化流程
```

**规则**：核心任务步骤不超过 3 步，否则必须优化。

## 四、反馈系统

### 即时反馈层级

| 层级 | 时机 | 方式 | 时长 |
|------|------|------|------|
| **微反馈** | Hover/Press | 颜色/缩放变化 | 120ms |
| **操作反馈** | 点击后 | Toast/状态变化 | 200ms appear |
| **过程反馈** | 操作进行中 | Loading/Progress | 实时 |
| **结果反馈** | 操作完成 | Toast/Inline/跳转 | 3-5s auto-dismiss |

### Toast vs Inline Message vs Notification

| 因素 | Toast | Inline Message | Notification |
|------|-------|---------------|-------------|
| **重要性** | 中（告知即可） | 高（需用户处理） | 高（异步事件） |
| **位置** | 全局（右上/底部中） | 就近组件旁 | 全局通知中心 |
| **生命周期** | 3-5s 自动消失 | 用户手动关闭 | 持久直到处理 |
| **适用** | 操作成功/失败 | 表单校验/区域错误 | 系统消息/后台任务 |

## 五、状态设计

### 每个组件的 6 种状态

```
┌─────────────────────────────────────────┐
│ Default → Hover → Active → Focus       │
│                                         │
│ Loading (骨架屏)                        │
│ Empty (空态引导)                        │
│ Error (错误提示)                        │
│ Disabled (禁用态)                       │
│ Selected (选中态)                       │
│ Partial (部分数据态)                    │
└─────────────────────────────────────────┘
```

### 空态设计规范

| 类型 | 展示 | 操作 |
|------|------|------|
| 首次使用 | 引导插图 + 说明 + CTA | "创建第一个..." |
| 搜索无结果 | 中性插图 + 建议 | "修改关键词/清除筛选" |
| 筛选无结果 | 简短文案 | "清除所有筛选条件" |
| 网络错误 | 错误图标 + 原因 + 操作 | "重试" 按钮 |
| 权限不足 | 锁图标 + 说明 | "申请权限" 链接 |

## 六、动效使用决策

### 何时使用动效

| 场景 | 是否需要 | 类型 | 时长 |
|------|---------|------|------|
| 元素出现/消失 | ✅ 是 | fade + slide | 200ms |
| 状态切换 | ✅ 是 | 颜色/尺寸过渡 | 150ms |
| 列表排序/过滤 | ✅ 是 | layout 动画 | 200ms |
| 页面跳转 | ⚠️ 可选 | route 过渡 | 250ms |
| 加载提示 | ✅ 是 | skeleton shimmer | 1.5s loop |
| 成功/庆祝 | ❌ 不用 | — | — |
| 纯装饰 | ❌ 不用 | — | — |

### 动效原则

```
1. 动效是功能信号，不是表演
2. 快进 > 慢出（用户等待感知短）
3. 时长 ≤ 350ms（>350ms 感觉拖沓）
4. 同时只 1 个动效引导注意力
5. 支持 prefers-reduced-motion
```

## 七、交互反模式

| 反模式 | 问题 | 修复 |
|--------|------|------|
| 操作无反馈 | 用户不确定是否生效 | 加 Toast/状态变化 |
| 过度确认 | 每个操作都弹 Modal | 仅破坏性操作确认 |
| 隐藏关键操作 | 重要按钮在 hover 才出现 | P0 操作始终可见 |
| 自动关闭弹窗过快 | 用户来不及读 | ≥ 3s 或手动关闭 |
| Tab 内容跳动 | 切换 Tab 页面高度变化 | 固定 Tab 区域高度或过渡 |
| 无限加载无进度 | 不知道要等多久 | 加进度条/skeleton |
| 表单全部必填 | 用户心理压力大 | 标记"选填"，必填自然 |
